# 8. Ready-to-paste prompt for a coding agent

[← Contents](README.md)

To paste as is into Claude Code (or another agent), driving it phase by phase
(see [Roadmap](07-roadmap.md)).

````markdown
You are a senior Go developer. Build "Watchoo", a GitHub repository monitoring tool.

## Goal
A single Go binary offering a CLI and a local web interface to track a list of GitHub repositories:
new commits, authors/contributors, date of the last activity, evolution over time.

## Technical constraints
- Go, latest stable version (fixed in go.mod), modules, code in internal/, entry point cmd/watchoo.
- CLI: spf13/cobra + spf13/viper (YAML config + env variables).
- Authentication: the GitHub CLI `gh` is a mandatory prerequisite for the MVP (optional since V2:
  without `gh`, repositories are tracked via local Git clones, see 03-architecture.md). The token is obtained only with
  `gh auth token`, fetched again at every sync, never stored (no config, no database, no logs). init
  checks `gh auth status`. Mostly private repositories: no GitHub write route is ever called.
- GitHub: google/go-github, without golang.org/x/oauth2 (the token is set by the provider's HTTP
  transport). Pagination, ETag/If-None-Match (in-memory cache), rate limit respect (wait for the
  reset when the quota is exhausted).
- Storage: SQLite via modernc.org/sqlite (no CGO), migrations with pressly/goose,
  typed queries generated with sqlc (schema read from the goose migrations, optional filters via sqlc.narg).
- Web: net/http + go-chi/chi router (route groups, middlewares), html/template, HTMX, DaisyUI (Tailwind) with CSS generated by the
  standalone Tailwind CLI (no Node), assets embedded with embed. Listens on 127.0.0.1 by default.
- Logs: log/slog. Bounded concurrency with errgroup (max 4 repositories synced in parallel).
- Provider abstraction (interface) to add GitLab/Gitea later.

## Data model
repositories, branches, contributors, contributor_emails, commits, commit_branches, sync_runs
(see 04-data-model.md).
commits: key (repo_id, sha), columns author_id, committer_id, message, authored_at, committed_at,
additions, deletions, url — a commit is stored only once per repository.
commit_branches(repo_id, sha, branch_id): on which tracked branches each commit was seen.
Index on commits(repo_id, committed_at DESC), commits(author_id, committed_at DESC) and
commit_branches(branch_id).

## Workspaces
One directory = one monitored group (e.g. a class's undergraduate projects). `watchoo init` creates
.watchoo/ (config.yaml, watchoo.db, .gitignore; permissions 0700/0600) in the current directory and
refuses if it already exists. The other commands look for .watchoo/ in the current directory then
the parents, like Git; -C <directory> or WATCHOO_DIR to designate another one. One SQLite database
per workspace.
See 10-workspaces.md.

## CLI commands
init, repo import <file.csv> (columns repo, label, branches; checks access, summary, idempotent, --dry-run),
repo add (all branches by default, --branch to restrict by list or pattern)|list|remove, sync, log (--repo --author --since -n), contributors, status,
serve (--addr --interval: 30 min default, 15 min minimum, refuses below). Global --json option.
Dedicated `tui` command: interactive mode with Bubble Tea (bubbletea + bubbles + lipgloss), built in
phase 3. The other commands are never interactive: plain text table (lipgloss/table) or JSON.
Respect of NO_COLOR.

## Web interface
Dashboard (one card per repository + feed of the latest commits), repository detail (history,
filters, 90-day chart), contributors page, settings page (repository addition, manual sync, API quota).

## Skills
The project's skills are installed from skills.sh (npx skills add), in .agents/skills/ with links
in .claude/skills/ and .vibe/skills/, locked by skills-lock.json. Use goland for Go,
semver and semver-changelog for versions and the CHANGELOG. Install no skill without approval.
See 11-skills.md.

## Working method
- Work phase by phase: 1) foundations, 2) GitHub provider, 3) sync + CLI + TUI, 4) web, 5) polish.
- At every phase: code, tests (httptest to simulate the GitHub API), go vet, then a summary of what works.
- CI uses neither real gh nor real GitHub: gh is mocked (Go interface + fake binary compiled from
  internal/auth/testdata/fakegh, path set via github.gh_path). See 09-testing.md.
- Incremental sync: never re-download a commit already in the database.
- Never write the token in clear in the logs.

Start with phase 1 and propose the tree before writing code.
````

> Tip: also point the agent at this `documentation/` folder, the reference in case of doubt.
